# S13 — ISO/IEC 25010 product quality model

Source: ISO/IEC 25010 (SQuaRE) product quality model. Eight characteristics, each
with sub-characteristics. Used here as the **completeness check** — it guarantees
the other fourteen standards leave no quality dimension unexamined.

## Characteristics and sub-characteristics, mapped

| Characteristic | Sub-characteristics | Where covered |
|---|---|---|
| **Functional suitability** | completeness, correctness, appropriateness | S13-C01..C04 |
| **Performance efficiency** | time behaviour, resource utilization, capacity | S05 |
| **Compatibility** | co-existence, interoperability | S13-C05..C07 |
| **Usability** | appropriateness recognizability, learnability, operability, user error protection, UI aesthetics, accessibility | S13-C08..C13, S12 |
| **Reliability** | maturity, availability, fault tolerance, recoverability | S05 |
| **Security** | confidentiality, integrity, non-repudiation, accountability, authenticity | S01–S04 |
| **Maintainability** | modularity, reusability, analysability, modifiability, testability | S13-C14..C19 |
| **Portability** | adaptability, installability, replaceability | S13-C20..C24 |

---

## Controls not already covered elsewhere

### Functional suitability

- **S13-C01** *Completeness*: every model family available on the endpoint has
  coverage; every feature the README claims is demonstrated.
- **S13-C02** *Correctness*: outputs are correct and current; no stale model IDs, no
  Region claims that no longer hold.
- **S13-C03** *Appropriateness*: the sample solves the reader's actual task — calling
  the endpoint successfully — rather than an abstract exercise.
- **S13-C04** Stated inventory counts match the executed evidence.

### Compatibility

- **S13-C05** *Interoperability*: OpenAI- and Anthropic-SDK paths both demonstrated
  where the endpoint supports them.
- **S13-C06** *Co-existence*: the sample does not require a bespoke environment; it
  runs in a standard virtualenv alongside other work.
- **S13-C07** No global state mutation that would affect a reader's other code
  (no monkey-patching, no environment variables set permanently).

### Usability

- **S13-C08** *Recognizability*: a reader can tell within seconds whether this
  repository serves their need.
- **S13-C09** *Learnability*: progression from simple to advanced within each
  notebook; the first cell that calls the API is simple.
- **S13-C10** *Operability*: setup is a documented, short sequence that works.
- **S13-C11** *User error protection*: predictable failure modes are pre-empted with
  a check and a clear message (missing credentials, wrong Region, missing model).
- **S13-C12** Error messages tell the reader what to do next.
- **S13-C13** *Accessibility*: output is plain text tables, readable in any viewer,
  not dependent on colour or graphics.

### Maintainability

- **S13-C14** *Modularity*: shared machinery in one module with a single
  responsibility.
- **S13-C15** *Reusability*: helper functions are usable outside the notebook that
  introduced them.
- **S13-C16** *Analysability*: a reader can locate the code responsible for any
  behaviour quickly — consistent structure, predictable naming.
- **S13-C17** *Modifiability*: changing a model ID or Region is a one-line edit in
  one place per notebook.
- **S13-C18** *Testability*: the whole artefact is executable end to end by a script.
- **S13-C19** Consistent structure across sibling notebooks lowers the cost of
  understanding the second one.

### Portability

- **S13-C20** *Adaptability*: no hardcoded machine-specific paths; no dependence on
  a particular OS.
- **S13-C21** Region is a parameter, not a constant buried in a helper.
- **S13-C22** *Installability*: `pip install -r requirements.txt` is sufficient.
- **S13-C23** *Replaceability*: a reader can swap the model ID and the code still
  works, or fails with a clear message.
- **S13-C24** Works on a current Python version without deprecation warnings.
